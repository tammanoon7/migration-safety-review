เอกสารนี้ครอบคลุมช่องที่ **ยังไม่ได้ทดสอบ** ในผลเปรียบเทียบ ได้แก่

| ช่อง | สถานะ | เหตุผล |
|------|-------|--------|
| case4 ฝั่ง B (AI + Skill) | **รันแล้ว** (คนรันเองตามขั้นตอนด้านล่าง ผลดิบอยู่ที่ `evaluation/case4_B.md`) | agent รอบแรกถูกระบบ safeguards ของโมเดลหยุดก่อนได้คำตอบ จึงให้คนรันแทน |

ขั้นตอนเดียวกันใช้รันซ้ำเคสอื่นได้ทั้งหมดด้วย

## หลักการ: ต้องแยกเซสชัน และห้ามเห็นเฉลย

- แต่ละรอบ = เซสชันใหม่ (เปิด chat ใหม่ หรือ `claude` ใหม่) ไม่ต่อจากเซสชันอื่น
- **ฝั่ง A (AI ปกติ):** ต้องไม่มี Skill ให้เห็น
  - ใช้โฟลเดอร์ว่างที่ไม่มี `.claude/skills/migration-safety-review/` และไม่มี `~/.claude/skills/migration-safety-review/` หรือใช้ AI บนเว็บที่ยังไม่ได้วาง SKILL.md
- **ฝั่ง B (AI + Skill):** ติดตั้ง Skill ตามหัวข้อ "ติดตั้ง" ใน `README.md`
- **ทุกฝั่ง:** ห้ามเปิดหรือวาง `examples/test-cases.md` (มีเฉลย) ให้ AI เห็น และอย่าให้ AI เปิดโฟลเดอร์ `evaluation/` ที่มีผลของรอบอื่น
  - วิธีที่ง่ายที่สุดคือคัดลอกเฉพาะไฟล์ใน `fixtures/` ไปไว้โฟลเดอร์ทดสอบชั่วคราวข้างนอกโปรเจกต์นี้

## ขั้นตอนรัน case4 ฝั่ง B

1. สร้างโฟลเดอร์ทดสอบชั่วคราว เช่น `scratch-case4-B/` นอกโปรเจกต์นี้
2. คัดลอก `fixtures/case4_irreversible_runpython.py` ไปไว้ในนั้น
3. คัดลอกโฟลเดอร์ `.claude/skills/migration-safety-review/` ไปไว้ใน `scratch-case4-B/.claude/skills/` (ไม่ต้องคัดลอก `examples/`)
4. เปิดเซสชันใหม่ในโฟลเดอร์นั้น แล้วส่ง prompt นี้ตรง ๆ

       /migration-safety-review ตรวจ migration นี้ให้หน่อย

   แล้วแนบเนื้อไฟล์ `case4_irreversible_runpython.py` (หรือสั่งให้อ่านไฟล์นั้น) ข้อมูลบริบท (PostgreSQL, ตาราง events ประมาณ 30 ล้านแถว) อยู่ในคอมเมนต์ต้นไฟล์อยู่แล้ว ห้ามเพิ่มข้อมูลอื่น
5. เก็บคำตอบดิบทั้งหมดโดยไม่แก้ ลงไฟล์ `evaluation/case4_B.md`
6. ตรวจเทียบเฉลยใน `examples/test-cases.md` ทีละข้อ (หลังรันเสร็จแล้วเท่านั้น) ตามเกณฑ์ 8 ข้อใน README หัวข้อ 7
7. นำตัวเลขที่ได้ไปแก้ในตารางของ README (แทนคำว่า "ยังไม่ได้ทดสอบ") และแก้ผลรวมของฝั่ง B ให้ตรงกับผลดิบ

## เกณฑ์ตรวจเทียบเฉลย (ใช้ชุดเดียวกับ README)

1. เจอความเสี่ยงที่ฝังไว้กี่จุด (นับจากรายการในเฉลย) โดยต้องชี้ operation ถูกตัวและระบุประเภทปัญหาถูก
2. ชี้ operation ถูกตัว ไม่ใช่พูดกว้าง ๆ
3. ระดับความรุนแรงสมเหตุผลเทียบเฉลย
4. false positive ที่ case5
5. ให้ query ตรวจข้อมูลก่อนรัน (ใช่/ไม่)
6. มีแผนถอยกลับ ระบุว่าอะไรถอยแล้วข้อมูลไม่กลับ (ใช่/ไม่)
7. บอกสิ่งที่ไฟล์บอกไม่ได้ (ใช่/ไม่)
8. ไม่สรุปว่า "ปลอดภัย" ลอย ๆ (ใช่/ไม่)

## ข้อควรระวัง

- อย่ารันคำสั่ง migrate / makemigrations กับ fixtures ใด ๆ ไฟล์พวกนี้ไว้ให้อ่านเท่านั้น
- ผลของ LLM แต่ละรอบไม่เหมือนกันทุกครั้ง ถ้ารันหลายรอบให้เก็บทุกรอบแยกไฟล์ (เช่น `case4_B_run2.md`) แล้วรายงานทั้งหมด
